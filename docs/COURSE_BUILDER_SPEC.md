# Course Builder — Implementation Specification

A complete blueprint for rebuilding the CurioQuest Academy Course Builder on another Next.js / Firebase platform. Covers the admin UI, data layer, Firestore schema, security rules, indexes, and supporting services.

**Stack assumed:** Next.js (App Router), React, TypeScript, Firebase (Firestore client SDK for reads, Admin SDK for trusted writes), Tailwind + shadcn/ui, Lucide icons, Sonner toasts, Stripe for paid courses, an LLM provider (OpenAI-compatible) for AI content generation.

---

## 1. Overview

The Course Builder is a three-surface admin workflow plus a supporting data layer:

| Surface | Route | Purpose |
|---|---|---|
| Academy dashboard | `/portal/admin/academy` | Course list, stats, publish/delete actions |
| Course metadata forms | `/portal/admin/academy/courses/new` and `/courses/[id]/edit` | Title, copy, instructor, difficulty, tags, pricing, thumbnail, publish state |
| Content builder | `/portal/admin/academy/courses/[id]/content` | Module/lesson tree CRUD, reordering, per-type content editors, AI generation tools |

Mental model: **Course → Modules → Lessons**. A course is marketing/metadata + pricing. Modules are ordered groupings. Lessons carry the actual content, typed by `contentType`.

## 2. Firestore Schema

All collections use an `lms_` prefix. Documents are plain objects with `Timestamp` fields (`createdAt`/`updatedAt`). ID is stored inside the doc and equals the Firestore doc ID.

### 2.1 `lms_courses` — `CourseDoc`

```ts
interface CourseDoc {
  id: string;
  title: string;
  slug: string;                          // derived from title, lowercase-hyphenated
  description: string | null;
  shortDescription: string | null;
  thumbnailUrl: string | null;           // cached display URL (see images)
  thumbnailImageId: string | null;       // reference into `images` collection
  previewVideoUrl: string | null;
  categoryId: string | null;
  instructorName: string;
  instructorBio: string | null;
  instructorImageUrl: string | null;
  difficultyLevel: "beginner" | "intermediate" | "advanced";
  estimatedDurationMinutes: number | null;
  minSubscriptionTierId: string | null;  // optional tier gating (nullable)
  isFeatured: boolean;
  isPublished: boolean;
  publishedAt: Timestamp | null;
  tags: string[];
  learningOutcomes: string[];
  prerequisites: string[];
  enrollmentCount: number;
  // Pricing
  priceInCents: number;                  // 0 when isFree
  compareAtPriceInCents: number | null;  // strikethrough "was" price
  isFree: boolean;
  stripePriceId: string | null;
  stripeProductId: string | null;
  createdAt: Timestamp;
  updatedAt: Timestamp;
}
```

Notes:
- `slug` is generated by `generateSlug(title)` — lowercase, non-alphanumeric → `-`, trimmed. Used for the public `/academy/courses/[slug-or-id]` deep link.
- `publishedAt` is set once by `publishCourse()` (a no-op if already published).
- `enrollmentCount` is denormalized — incremented by the enrollment API, never by the client.
- Prices are always integers in cents; UI converts to dollars for display.

### 2.3 `lms_lessons` — `LessonDoc`

```ts
interface LessonDoc {
  id: string;
  moduleId: string;
  courseId: string;                    // denormalized for flat queries
  title: string;
  slug: string;
  description: string | null;
  contentType: ContentType;
  videoUrl: string | null;
  videoDurationSeconds: number | null;
  textContent: string | null;          // rich text / markdown; ALSO the quiz store
  downloadUrl: string | null;
  gptConfig?: GPTLessonConfig | null;        // only when contentType === "gptLesson"
  interviewConfig?: StudentInterviewConfig | null; // only for "studentInterview"
  imageId: string | null;              // `images` doc ref
  imageUrl: string | null;             // cached display URL
  isPreview: boolean;                  // free-access flag for non-enrolled viewers
  sortOrder: number;
  createdAt: Timestamp;
  updatedAt: Timestamp;
}

type ContentType =
  | "video" | "text" | "quiz" | "assignment"
  | "download" | "live" | "gptLesson" | "studentInterview";
```

**Field-by-type contract** — the save path nulls out fields not relevant to the chosen type:

| contentType | Fields used |
|---|---|
| `video` | `videoUrl`, `videoDurationSeconds` |
| `text` | `textContent` (markdown/HTML) |
| `quiz` | `textContent` (structured markdown — §6) |
| `assignment` | `textContent`, optional `downloadUrl` |
| `download` | `downloadUrl` |
| `live` | `videoUrl` (meeting link), `videoDurationSeconds` |
| `gptLesson` | `gptConfig` object |
| `studentInterview` | `interviewConfig` object |

### 2.7 `images` — `ImageDoc` (shared platform image store)

Thumbnails and lesson images are stored **as base64 inside Firestore**, not in Cloud Storage (simple, under the 1 MB document limit):

```ts
interface ImageDoc {
  id: string;
  name: string;
  description?: string;
  category: "hero" | "about" | "team" | "services" | "testimonials"
          | "logos" | "icons" | "backgrounds" | "marketing" | "portal" | "other";
  mimeType: string;
  base64Data: string;          // the actual image payload
  width?: number;
  height?: number;
  size: number;                // bytes
  tags?: string[];
  isActive: boolean;
  createdAt: Timestamp;
  updatedAt?: Timestamp;
  createdBy?: string;
}
```

Upload flow: validate `image/*` + < 1 MB → `compressImage()` (canvas resize) → `fileToBase64()` → write `images` doc → store `imageDoc.id` + a data-URL on the lesson/course. Alternative: swap for Cloud Storage + download URLs if you outgrow the 1 MB cap.

## 3. Data-Access Layer — `lib/firebase-lms.ts`

A single module owns all catalog CRUD. Client-side Firestore SDK (not Admin) — the rules restrict writes to admins. Export inventory:

### Categories
- `createCategory({name, description?, icon?, color?, sortOrder?})` — auto-slugs
- `getCategories()` — ordered by `sortOrder`
- `updateCategory(id, updates)`, `deleteCategory(id)`

### Courses
- `createCourse(data)` — auto-slugs, defaults `isPublished:false`, `isFeatured:false`, `enrollmentCount:0`, `isFree:true`, `priceInCents:0`, `publishedAt:null`, `stripePriceId/stripeProductId:null`
- `getCourse(id)`, `getCourseBySlug(slug)`
- `getCourses(options?)` — optional `isPublished`, `isFeatured`, `categoryId` filters
- `updateCourse(id, partial)`, `publishCourse(id)` (sets `isPublished:true`, `publishedAt` once)
- `deleteCourse(id)` — deletes the course doc **and all its modules and lessons** (batched)

### Modules
- `createModule({courseId, title, description?, sortOrder})`
- `getModules(courseId)` — `where courseId ==` + `orderBy sortOrder`
- `updateModule(id, partial)`, `deleteModule(id)` — deletes the module's lessons too
- `reorderModules(courseId, orderedIds[])` — writes each doc's `sortOrder = index`

### Lessons
- `createLesson(data)` — requires `moduleId`, `courseId`, `title`, `contentType`, `sortOrder`; auto-slugs; nulls unused type fields
- `getLessons(moduleId)`, `getCourseLessons(courseId)`
- `updateLesson(id, partial)`, `deleteLesson(id)`
- `reorderLessons(moduleId, orderedIds[])`
- `getCourseWithModulesAndLessons(courseId)` — composite fetch: course + modules (sorted) + lessons grouped per module (sorted); the content builder's single data load

### Utility
- `generateSlug(title)` — `title.toLowerCase().replace(/[^a-z0-9]+/g,"-").replace(/^-|-$/g,"")`
- `subscribeToCourses(cb)` / `subscribeToWorkshops(cb)` — `onSnapshot` live feeds for dashboards
- `getAcademyStats()` — `Promise.all` count of courses/lessons/workshops/enrollments/certificates

Every function starts with `if (!db) throw new Error("Firebase not initialized")` and strips `undefined` values before writing (Firestore rejects them — use `Object.fromEntries(Object.entries(o).filter(([,v]) => v !== undefined))`).

## 4. Admin UI — Page by Page

### 4.1 Academy dashboard (`/portal/admin/academy`)

- Stat cards row: total courses, lessons, workshops, enrollments, certificates (from `getAcademyStats()`)
- Course table/cards: title, status badge (Published/Draft), enrollment count, price
- Row actions: **Edit** (→ edit page), **Content** (→ content builder), **Publish/Unpublish** toggle, **Delete** (AlertDialog confirm)
- Tabs/links to sibling admin pages: Students, Purchases, GPT Reviews, Guardian Links
- "New Course" button → `/courses/new`

### 4.2 New course (`/courses/new`)

Single-column form, Card-wrapped sections:

- **Basics**: title (required), short description, full description (Textarea), category Select (populated via `getCategories()`), tags (chip input: add on Enter/button, X to remove)
- **Instructor**: name (prefilled default), bio
- **Details**: difficulty Select (beginner/intermediate/advanced), estimated duration in **hours** (converted `*60` → minutes on save), featured Switch
- **Outcomes & prerequisites**: two chip-input lists (`learningOutcomes[]`, `prerequisites[]`)
- Submit → `createCourse()` → `router.push(/courses/{id})` redirect into the edit/content flow

New courses are created **unpublished and free** — pricing and publish are edit-time decisions.

### 4.3 Edit course (`/courses/[id]/edit`)

Same fields as new, plus the launch-critical controls:

- **Publish switch** — `isPublished` toggle with Draft/Published status text
- **Pricing card** — `isFree` switch; when paid: price input (`value={(priceInCents/100).toFixed(2)}` → `Math.round(dollars*100)`), compare-at price input, and a live "NN% discount applied" hint when `compareAt > price`
- **Thumbnail** — file input → `compressImage()` → `uploadImage()` into `images` → `thumbnailImageId` + data-URL preview stored on the course
- Save → `updateCourse(id, {...})` with `priceInCents: isFree ? 0 : priceInCents`

### 4.4 Content builder (`/courses/[id]/content`) — the core UX

One page, `getCourseWithModulesAndLessons(courseId)` as the single load, local state `modules: ModuleWithLessons[]` where each module embeds `lessons: LessonDoc[]`.

**Structure:**
- Header: course title, back link, "AI Generate Syllabus" button, "Add Module" button
- Module list: `Collapsible` per module — grip handle, expand chevron, title, lesson count badge, edit/delete icons, up/down arrows (`reorderModules`)
- Inside each module: lesson rows — content-type icon, title, preview badge (`Eye`/`EyeOff`), edit/delete, up/down arrows (`reorderLessons`), "Add Lesson" button per module
- Empty state card prompting first module

**Module dialog** — title + description only (create or edit mode).

**Lesson dialog** — the big one. Fields:
- Module selector (which module it belongs to)
- Title, description
- `isPreview` Switch — "Preview" badge eye icon
- **Content-type picker**: grid of 8 option cards (icon + label + one-line description): Video, Text/Article, Quiz, Assignment, Downloadable, Live Session, GPT Lesson, AI Student Interview
- Conditional fields per type:
  - `video`: `videoUrl` + duration minutes + live `VideoPreview` iframe (YouTube/Vimeo/Loom ID extraction via `extractVideoId`)
  - `text`: `textContent` Textarea + `AIEnhanceButton` to rewrite/polish
  - `quiz`: informational note — questions live in `textContent` in the markdown grammar (§6); AI Quiz/Exam generator dialogs feed it
  - `download`: `downloadUrl`
  - `gptLesson`: full config form — topicArea, learningObjective, audience (adult/minor), gradeBand, prerequisites (newline list → array), tutorPersona Select (generic/math/reading/lifeSkills/custom + custom instructions field), estimatedDuration, maxHints, requiresGuardianConsent (forced+disabled for minors), requiresInstructorReview, quizPassingPercentage (0–100 clamped), rubricPassingScore (0–4 clamped), maxTransferAttempts; `promptVersion` is set automatically from a shared constant
  - `studentInterview`: systemPrompt Textarea (default imported from `lib/interview-defaults`), minTurns, maxTurns (validated `max >= min`), duration, audience, gradeBand, guardian consent
- `LessonImagePicker` component — browse/select from the `images` library or upload; stores `imageId` + `imageUrl`
- Save → `createLesson` or `updateLesson`; on success `loadCourseContent()` reloads the tree

**Reorder**: optimistic local swap of array positions, then `reorderModules`/`reorderLessons` writes `sortOrder = index` for every item in the parent collection; on failure toast + reload.

**Delete**: AlertDialog with item title; `deleteModule` cascades its lessons; `deleteCourse` cascades modules+lessons.

### 4.5 AI content tools (`components/academy/ai-content-tools.tsx`)

Five generator components, each a Dialog: pick type → tune params → call `/api/ai/course-generate` → preview result → "Apply" button:

| Component | Output | Applied to |
|---|---|---|
| `AISyllabusGenerator` | `CourseOutline { modules: [{title, description, lessons: [{title, description, contentType}]}] }` | `handleApplySyllabus` — loops `createModule` + `createLesson` to scaffold the whole course |
| `AILessonGenerator` | `GeneratedLesson {title, description, content, ...}` | Fills lesson form fields (`textContent`, title, description) |
| `AIQuizGenerator` | `GeneratedQuiz {title, passingScore, timeLimit, questions[]}` | Formats questions as markdown (§6) into `textContent`, sets type `quiz` |
| `AIExamGenerator` | `GeneratedExam` | Same as quiz |
| `AIEnhanceButton` | improved text string | Overwrites `textContent` |
| `AIToolbar` | container | Groups them |

Client calls a thin `lib/ai-course-generator.ts` which `fetch`es `/api/ai/course-generate` (server route, LLM call happens server-side — keys never in the browser).

## 6. Quiz Storage Format — markdown in `textContent`

Quiz lessons store their questions as **structured markdown inside `textContent`** (no separate question collection). The AI generators emit this format; `parseQuizContent()` in the server lib parses it back.

Grammar:

```markdown
# Quiz Title

**Passing Score:** 70%
**Time Limit:** 10 minutes

## Questions

### 1. What is 2 + 2?
A) 3
B) 4 ✓
C) 5

*Explanation: 2+2 equals 4.*

### Question 2: Sky color?
A) Blue ✓
B) Green
```

Parser rules (from `parseQuizContent`):
- `# Title` → quiz title (first single-# header)
- `Passing Score: NN%` → `passingScore` (default 70)
- `### N. text` or `### Question N: text` or any `###`/`##` header → new question (`id` = `q{index}`)
- `A) option` / `B. option` → option; `✓`/`✔` suffix marks `correctAnswer` (option index)
- `*text*` line → `explanation`

Server GET strips `correctAnswer`/`explanation`; POST scores against the parsed authoritative copy. This means **the builder never needs a question-editing UI** — it edits markdown (or AI-generates it) — but the format is a portability wart: a re-implementation could instead store a `questions[]` array field or a separate `lms_quiz_questions` subcollection and keep the same scoring API.

## 7. Security Model

### 7.1 Firestore rules

```
match /lms_categories/{id}     { allow read: if true; allow write: if isAdmin(); }
match /lms_courses/{id}        { allow read: if true; allow write: if isAdmin(); }
match /lms_course_modules/{id} { allow read: if true; allow write: if isAdmin(); }
match /lms_lessons/{id}        { allow read: if true; allow write: if isAdmin(); }
```

- Catalog reads are **public** (the marketing catalog reads them anonymously; published-state filtering happens in queries/UI)
- Writes are **admin-only** via an `isAdmin()` helper that reads a server-written role bridge doc: `users/{request.auth.uid}.role in ["admin","superadmin"]` — the bridge doc is created by an API route on login (`/api/auth/sync-profile`) since the app's profile lives in a different collection (`teamMembers`)
- Learner collections (`lms_enrollments`, `lms_lesson_progress`, `lms_quiz_attempts`, `lms_certificates`, `lms_course_purchases`) are read-own-or-admin and **write-denied for all clients** — every write goes through server API routes using the Admin SDK
- Because rules blocks OR together, every locked collection must also be excluded from any broad `match /{document=**}` catch-all, or the catch-all silently grants access

### 7.2 Required composite indexes

```
lms_course_modules:  courseId ASC + sortOrder ASC
lms_lessons:         moduleId ASC + sortOrder ASC
lms_lessons:         courseId  ASC + sortOrder ASC
lms_lesson_progress: enrollmentId ASC + isCompleted ASC
lms_lesson_progress: odUserId ASC + courseId ASC
lms_lesson_progress: odUserId ASC + lessonId ASC + completedAt DESC
lms_enrollments:     userId ASC + enrolledAt DESC
lms_quiz_attempts:   odUserId ASC + lessonId ASC + completedAt DESC
lms_certificates:    odUserId ASC + issuedAt DESC
lms_course_purchases: odUserId ASC + createdAt DESC
```

The module/lesson `sortOrder` pairs are what the content builder's ordered tree needs; progress/enrollment indexes feed recalculation and reporting.

## 8. Server-Side Trust Boundaries (recommended, as built)

The builder itself can stay client-side (admin-gated rules suffice), but everything learners touch is server-mediated — keep that split when re-implementing:

| API route | Job |
|---|---|
| `POST /api/auth/sync-profile` | Writes `users/{uid}` role doc so `isAdmin()` works |
| `POST /api/lms/enroll` | Authenticated, idempotent free enrollment |
| `POST /api/lms/progress` | Ownership-checked lesson completion → recalculates enrollment % → issues certificate once |
| `GET+POST /api/lms/quiz` | Returns questions sans answers; scores submissions server-side into `lms_quiz_attempts` |
| `POST /api/lms/certificate` | Issues certificate only when server-verified complete |
| `POST /api/stripe/course-checkout` | Auth-required; server-derived identity; Stripe session for paid items, direct enroll for free |
| `POST /api/stripe/webhook` | Idempotent paid enrollment on `purchaseId`; refund revokes access |
| `POST /api/ai/course-generate` | LLM content generation (syllabus/lessons/quizzes) server-side |

Auth pattern for learner APIs: client sends Firebase ID token in `Authorization: Bearer`; server `admin.auth().verifyIdToken()`, resolves the app's user record, and derives identity — **never trusts a client-supplied `userId`**.

## 9. Stripe / Pricing Integration

- Course doc holds `priceInCents`, `compareAtPriceInCents`, `isFree`, optional `stripePriceId`/`stripeProductId`
- Checkout creates a Stripe Checkout Session with `price_data` line items built from the course docs (no pre-created Products required), `customer_email` from the authenticated user, `metadata.courseIds`
- Free courses (`isFree` or `priceInCents === 0`) skip Stripe entirely → direct `/api/lms/enroll` → redirect `/portal/my-courses`
- Webhook `checkout.session.completed` → purchase doc + enrollment (idempotent); `charge.refunded` → `paymentStatus:"refunded"` + enrollment revocation

4. **Indexes** — deploy §7.2 `firestore.indexes.json` entries before first real query

9. **AI tools** (optional) — port `lib/ai-course-generator.ts` + dialog components + a server `/api/ai/course-generate` route
10. **Learner APIs** — enroll/progress/quiz/certificate routes; learners must never write these collections directly
11. **Stripe** (optional) — checkout + webhook per §9

## 11. Known Warts Worth Fixing in a Rebuild

- **Quiz-in-markdown** — works but fragile; a `questions[]` field or subcollection is cleaner
- **`odUserId` vs `userId` keyspace split** — enrollments key on `userId`, progress/quizzes/certs on `odUserId`; unify on one field
- **Admin writes are client-side** — works because rules gate `isAdmin()`, but moving CRUD behind API routes gives you audit logging and role checks you control
- **Cascade deletes are N+1** — `deleteCourse` iterates modules→lessons client-side; a server batch/transaction is safer at scale
- **`getAcademyStats` counts full collections** — fine at small scale; use `getCountFromServer` or counters later
- **No module-level publish flag** — only lessons have `isPreview`; a `isPublished` per module/lesson would give staged rollouts
